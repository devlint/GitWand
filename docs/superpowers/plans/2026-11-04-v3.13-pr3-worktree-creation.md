# v3.13 PR 3 — Worktree creation service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Rust worktree service creates every worktree (worktree manager and AI task): it fetches the base, brings the `include` files, records the worktree, and lets the frontend run the trusted `setup` hook in a read-only terminal tab and then `url`.

**Architecture:** A new module `src-tauri/src/worktree/` holds slug, config, record, base, include, create and hook logic as plain functions over paths, testable with real repos. Thin commands in `commands/worktree.rs` expose `worktree_create`, `worktree_resolve_base`, `worktree_run_hook` (PTY via PR 2's `spawn_session`, behind `assert_hooks_trusted`) and `worktree_url`. The frontend gets one composable, `useWorktreeCreation`, which asks for trust, creates, runs setup in a setup tab and fetches the URL; the AI-task flow and `WorktreeManager.vue` call it. The dev-server mirrors every command in `dev-worktree-service.mjs`, and its old shell-interpolated worktree routes are rewritten with argument arrays.

**Tech Stack:** Rust (Tauri 2.12, portable-pty, serde), Vue 3 `<script setup>`, Vitest, Node dev-server (node-pty, `execFileSync`).

**Spec:** `docs/superpowers/specs/2026-11-04-v3.13-agent-workspaces-i-design.md` (§3, §4, §5, §10, §12 item 3). Builds on #281 (`worktree_trust.rs`, `useWorktreeHookTrust.ts`) and #282 (`terminal.rs` `spawn_session` / `SpawnKind::Command` / `event_sinks`, `worktree_processes.rs`).

## Global Constraints

- `safe_repo_path` on every user-supplied path; git always via `git_cmd().args([...])`, never interpolated (AGENTS.md).
- Hooks are read from the **main** worktree's `.gitwandrc` at the moment of the operation, and run only through `assert_hooks_trusted(cwd, hash)`; the hook runner runs exactly the hooks that call returns.
- `{name}` is `[a-z0-9][a-z0-9-]{0,62}`; `{path}`, `{branch}`, `{base}` are substituted shell-quoted. Env: `GITWAND_WORKTREE_NAME`, `GITWAND_WORKTREE_PATH`, `GITWAND_WORKTREE_BRANCH`, `GITWAND_WORKTREE_BASE`, `GITWAND_REPO_ROOT`. cwd = the new worktree. Shell: `$SHELL -lc` (Unix), `cmd /C` (Windows).
- Default dir: `<main>.worktrees/<slug>`; a relative `dir` resolves against the main worktree root.
- New branch has **no upstream tracking**.
- Record file: `$GIT_COMMON_DIR/gitwand/worktrees.json`, fields `path, branch, base_ref, base_commit, created_at, kind ("task"|"manual"), source_branch`.
- `url`: first non-empty stdout line, 10 s timeout.
- Every user-visible string in all 5 locales (`en`, `fr`, `es`, `pt-BR`, `zh-CN`).
- Each new command: `backend.ts` wrapper + `commandRegistry.ts` entry + dev-server route, same PR.
- Real git repos in tests; no Tauri mocks; `cargo fmt` and `cargo clippy -- -D warnings` clean. PTY / `ps` tests run outside the sandbox.

## Review Focus

1. A worktree path or branch containing spaces, quotes, `$` or `;`: placeholders must reach the hook as one literal argument — Task 5 `expand_quotes_hostile_values` runs the expansion through a real shell.
2. The fetch hangs (auth prompt, dead host): creation must not hang forever — Task 2 sets `GIT_TERMINAL_PROMPT=0` and a 20 s timeout, test `fetch_failure_falls_back_to_tracking_ref`.
3. A `.gitwandrc` changed between the trust answer and the hook run: the hook must refuse — Task 5 `run_hook_refuses_stale_hash`.
4. An `include` entry that is a symlink escaping the repo, or `../x`: refused, never copied — Task 3 `include_refuses_outside_paths`.
5. An AI task created by the new service must still close / merge back through the existing scratch flow until PR 4–5 (`validate_scratch_path` checks a `gitwand-scratch-` basename today) — Task 4 `recorded_task_is_accepted_by_scratch_discard`.

### Task 2: Base resolution + `worktree_resolve_base`

**Files:**
- Create: `apps/desktop/src-tauri/src/worktree/base.rs`, `apps/desktop/src-tauri/src/commands/worktree.rs`

**Interfaces:**
- Produces:
  - `base::BaseResolution { base_ref: String, commit: String, fetched_at: Option<u64>, fallback_reason: Option<String>, fallback_detail: Option<String> }` (Serialize, snake_case keys). Reasons: `"no-remote"`, `"no-default-branch"`, `"fetch-failed"`.
  - `base::resolve_default_base(main_root: &Path, fetch_timeout: Duration) -> Result<BaseResolution, String>`:
    1. remote = `branch.<current>.remote` if set and listed by `git remote`, else `origin` if listed, else → local HEAD with `no-remote`.
    2. default branch = target of `refs/remotes/<r>/HEAD`, else `main` if `refs/remotes/<r>/main` exists, else `master`; none → local HEAD with `no-default-branch`.
    3. `git fetch --quiet --no-tags <r> <default>` with `GIT_TERMINAL_PROMPT=0`, killed after `fetch_timeout` (command passes 20 s). Success → `<r>/<default>`, `fetched_at = now`.
    4. Failure → `<r>/<default>` if that ref exists, else local HEAD (current branch short name, or `HEAD` detached); `fetch-failed` + stderr in `fallback_detail`.
    5. No commit at all → `Err("This repository has no commit yet.")`.
  - `base::resolve_explicit_base(root: &Path, base: &str) -> Result<BaseResolution, String>`: refuses a leading `-`, `rev-parse --verify --quiet <base>^{commit}`.
  - `#[tauri::command] worktree_resolve_base(cwd) -> WorktreeBaseInfo { base: BaseResolution, dir: String }` (dir = `worktrees_dir` of the main root, for pre-filling the form). Async, `spawn_blocking`.
  - `backend.ts`: `interface BaseResolution { base_ref; commit; fetched_at: number|null; fallback_reason: "no-remote"|"no-default-branch"|"fetch-failed"|null; fallback_detail: string|null }`, `interface WorktreeBaseInfo { base; dir }`, `worktreeResolveBase(cwd)` → POST `/api/worktree-resolve-base`.

### Task 4: Create + `worktree_create`; scratch flow accepts recorded tasks

**Files:** Create `apps/desktop/src-tauri/src/worktree/create.rs`. Modify `commands/worktree.rs`, `lib.rs`, `commands/scratch.rs`, `src/utils/backend.ts`, `src/utils/commandRegistry.ts`.

  - `create::create_worktree(cwd: &Path, req: CreateRequest, fetch_timeout: Duration) -> Result<CreatedWorktree, String>`:
    1. `main = main_worktree_root(cwd)`; `slug = slugify(name)` or `Err("The name needs at least one letter or digit.")`.
    2. Branch: `req.branch` (validated by `git check-ref-format --branch`) or `task/<slug>`. If `refs/heads/<branch>` exists and `req.base` is `None`: check it out (no `-b`), base = that branch at its commit. If it exists and a base is given → `Err("Branch <b> already exists.")`.

    4. Path: `req.path` (must be absolute, must not exist or be an empty directory) or `<worktrees_dir>/<slug>`. For the default path and default branch only, on collision (path exists or branch exists) both get the smallest free suffix `-2`, `-3`, …; `name` becomes the suffixed slug.

    6. `record::upsert` with `source_branch` = main checkout's current branch (None if detached). For `Kind::Task` also write `branch.<b>.gitwandBase = commit` and `branch.<b>.gitwandSource = base_ref` (the existing merge-back guard keeps refusing when the main checkout lacks the base). Any failure here → `worktree remove --force` + `branch -D` (only a branch this call created), then Err.
