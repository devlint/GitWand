# v3.13 PR 2 — Terminal commands, exit codes and stopping a worktree's processes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The PTY layer can run a given command with an allow-listed environment and report its exit code. GitWand can stop every process it started for a worktree, and list or stop the processes still running there.

**Architecture:**
- `terminal.rs` gets an internal `spawn_session` that takes closures, so it can be tested without Tauri. `terminal_open` becomes a thin wrapper that adds an optional `on_exit` channel.
- A new `process_tree.rs` gives a read-only view of processes: pid, ppid, session id, working directory. It shells out to `ps` / `lsof` on macOS and reads `/proc` on Linux.
- The stop logic lives in `commands/worktree_processes.rs`, behind one command, `worktree_stop_processes`.
- On Windows, each PTY child goes into a Job Object that kills its whole tree.
- The dev-server mirrors all of it on a best-effort basis.

**Tech Stack:** Rust (portable-pty 0.9, libc on Unix, windows-sys 0.61 on Windows), TypeScript / Vue composables, Node dev-server (node-pty).

**Spec:** `docs/superpowers/specs/2026-11-04-v3.13-agent-workspaces-i-design.md` (§8, §10.1 `worktree_stop_processes`, §10.2, §12 item 2)

## Global Constraints

- **No new IPC path to run an arbitrary command from the frontend.** In this PR, `command` and `env` are a Rust-internal API (`spawn_session`). PR 3 exposes them only through the hook runner, which calls `assert_hooks_trusted` (spec §4 Trust). **(plan ruling, against spec §10.2: `shell_exec` already lets the frontend run user-authored commands, but repository commands must only enter through the trust gate)**
- **The exit code arrives on a separate optional channel**, `on_exit: Channel<TerminalExit>`, not as a final message on `on_output`. Every existing consumer of `Channel<String>` then stays unchanged. **(plan ruling, against spec §10.2's wording; same behavior)**
- **`env` allow-list:** exactly `GITWAND_WORKTREE_NAME`, `GITWAND_WORKTREE_PATH`, `GITWAND_WORKTREE_BRANCH`, `GITWAND_WORKTREE_BASE` and `GITWAND_REPO_ROOT`. Any other key is an error. Nothing is dropped silently, and a stripped secret can never come back (spec §10.2).
- **A command runs through the user's login shell**: `$SHELL -l -c <command>` on Unix, with `-l` only when `login_flag` accepts the shell, and `cmd /C <command>` on Windows (spec §4).
- **`worktree_stop_processes` acts only on a linked worktree of the repo given as `cwd`.** It refuses the main worktree, any path that is not a worktree, and GitWand's own process and process group.
- **Processes GitWand did not start are never killed unless `kill_foreign` is true**, which the "Stop all" click sets (spec §8 step 3).
- **Timings come from spec §8:** 500 ms after the session stop before the sweep; SIGTERM, then SIGKILL after 2 s.
- **Windows:** no cwd sweep in this PR, because reading another process's working directory needs its PEB. The Job Object covers every process GitWand started. **(plan ruling: on Windows, a foreign process still in the worktree goes unlisted, and PR 4's `git worktree remove` then fails on the locked folder and surfaces git's error)**
- **CI runs `cargo test` only on Linux and macOS**, and only `cargo check` / `clippy -D warnings` on Windows. Windows code must therefore compile cleanly with clippy, and its behavior is verified by reading.
- Before pushing: `cargo fmt`. Every new command: `backend.ts` wrapper, `commandRegistry.ts` entry and a dev-server route, all in the same PR.

## Review Focus

1. **A shell background job with its own process group** (`set -m; sleep 300 &`) must be gone after the session closes. That is the v3.12.1 gap. → Task 3, `close_kills_background_job_in_own_group`.
2. **A process that double-forked out of GitWand's tree** (reparented to pid 1) with its cwd in the worktree: it must be listed, and not killed while `kill_foreign` is false. → Task 4, `foreign_process_is_listed_not_killed`.
3. **`path` is the main worktree, `/`, or a folder outside the repo:** refuse and kill nothing. → Task 4, `refuses_main_worktree_and_non_worktree`.
4. **A worktree path with a space, or reached through a symlink:** both the cwd match and the session match must still work. → Task 2, `cwd_sweep_matches_symlinked_and_spaced_paths`.
5. **A command that exits with a non-zero code before writing any output:** the exit code must still arrive, after every output chunk. → Task 1, `command_exit_code_arrives_after_output`.

**Files:**
- Create: `apps/desktop/src-tauri/src/process_tree.rs`, declared in `lib.rs` as `mod process_tree;`.
- Test: in the same file, `#[cfg(all(test, unix))]`.

**Interfaces:**
- Produces:
  ```rust
  #[derive(Clone, Debug, Serialize)] pub(crate) struct ProcInfo { pub pid: u32, pub ppid: u32, pub name: String }
  pub(crate) fn list_processes() -> Vec<ProcInfo>;                     // `ps -A -o pid=,ppid=,comm=`; [] on Windows
  pub(crate) fn session_of(pid: u32) -> Option<u32>;                   // libc::getsid; None on error / Windows
  pub(crate) fn pids_with_cwd_under(root: &Path) -> Vec<u32>;          // root canonicalized first
  pub(crate) fn is_descendant(pid: u32, ancestors: &HashSet<u32>, procs: &[ProcInfo]) -> bool; // walks ppid, stops at 1/0/cycle
  ```
- How `pids_with_cwd_under` finds working directories:
  - **macOS:** `lsof -a -d cwd -F pn` over all processes. Read the `p`/`n` lines, canonicalize each `n` path, and keep it when it `starts_with(root)` component-wise.
  - **Linux:** read `/proc/<pid>/cwd` with `read_link`.
  - **Windows:** `Vec::new()`.
  - Unreadable entries are skipped.

### Task 3: Stop a session's whole process tree

**Files:**
- Modify: `apps/desktop/src-tauri/src/commands/terminal.rs` (`close_sessions`, `session_groups`).
- Modify: `apps/desktop/src-tauri/Cargo.toml`. Under `[target.'cfg(windows)'.dependencies]`: `windows-sys = { version = "0.61", features = ["Win32_Foundation", "Win32_System_JobObjects", "Win32_System_Threading"] }`. 0.61.2 is already in `Cargo.lock`.
- Test: `terminal.rs` tests.

**Interfaces:**
- Consumes: `process_tree::{list_processes, session_of}` (Task 2), and `PtyHandle.leader` (Task 1).
- Produces:
  ```rust
  pub(crate) fn sessions_under(root: &Path) -> Vec<u64>;            // ids whose PtyHandle.cwd starts_with(root)
  pub(crate) fn close_session_ids(ids: &[u64]) -> HashSet<u32>;      // closes them like terminal_close; returns their leader pids (for Task 4's "own" set)
  ```

Unix behavior:
- `close_sessions` still signals the groups it signals today.
- It also signals every pid whose `session_of(pid) == Some(leader)`, through `kill(pid, …)`, which covers background jobs with their own group and orphaned foreground jobs.
- It uses the same SIGHUP → grace → SIGKILL sequence, and never signals pid ≤ 1, our own pid, or a pid in our own group.

Windows behavior:
- `spawn_session` creates a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and assigns the child to it, through `OpenProcess(PROCESS_SET_QUOTA | PROCESS_TERMINATE, …, pid)`. The `HANDLE` is stored in the `PtyHandle` and closed in `Drop`.
- `close_sessions` calls `TerminateJobObject(job, 1)` before `child.kill()`.
- If the assignment fails, it logs and carries on: the behavior then degrades to today's, killing the leader only.

### Task 4: `worktree_stop_processes` command

**Files:**
- Create: `apps/desktop/src-tauri/src/commands/worktree_processes.rs`, declared in `commands/mod.rs` and registered in `lib.rs`.
- Modify: `apps/desktop/src/utils/backend.ts` (wrapper) and `apps/desktop/src/utils/commandRegistry.ts` (`worktree_stop_processes: { route: "/api/worktree-stop-processes" }`).
- Test: the same file, real repos.

**Interfaces:**
- Consumes: Task 2 and Task 3.
- Produces:
  ```rust
  #[tauri::command] pub(crate) async fn worktree_stop_processes(cwd: String, path: String, kill_foreign: bool) -> Result<Vec<ProcInfo>, String>; // survivors
  fn stop_processes_in(repo: &Path, worktree: &Path, kill_foreign: bool) -> Result<Vec<ProcInfo>, String>; // testable core, runs on spawn_blocking
  ```
  ```ts
  export interface ProcessInfo { pid: number; ppid: number; name: string }
  export function worktreeStopProcesses(cwd: string, path: string, killForeign: boolean): Promise<ProcessInfo[]>;
  ```

Algorithm, all of it on the blocking pool:
1. `repo = safe_repo_path(cwd, ".")`. `worktree = canonicalize(path)`. Then require that `worktree` equals a non-first entry of `git worktree list --porcelain` run in `repo`, canonicalized. Otherwise return `Err("Not a linked worktree of this repository: <path>")`.
2. `own = close_session_ids(&sessions_under(&worktree))`, plus `std::process::id()`.
3. Sleep 500 ms.
4. `procs = list_processes()`. `pids = pids_with_cwd_under(&worktree)`, minus our own pid. A pid counts as **owned** when `session_of(pid)` is in `own`, or `is_descendant(pid, &own, &procs)` holds.
5. Send SIGTERM to the owned pids, and also to the foreign ones when `kill_foreign` is true.
6. Wait up to 2 s, polling every 50 ms. Send SIGKILL to the targeted pids that are still alive.
7. Return `pids_with_cwd_under(&worktree)` taken again (minus our own pid), mapped to `ProcInfo` through `procs`. A pid missing from `procs` gets `name: "?"`.
