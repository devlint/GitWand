# v3.13 PR 4 — Worktree removal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every worktree removal (worktree manager, AI-task close, Git Tree "Delete worktree", merge-back cleanup, conflict-scratch discard) goes through one guarded sequence: guards → stop processes → snapshot → teardown → remove → branch → record (spec §7).

**Architecture:** two new modules in the worktree service, `worktree/guard.rs` (untouchable / owned) and `worktree/remove.rs` (prepare = guard + stop + snapshot; finish = guard + teardown gate + remove + prune + branch + record). Teardown runs in the frontend's read-only terminal tab between the two, through `worktree_run_hook(…, "teardown", …)`. One frontend state machine (`useWorktreeRemoval.ts`) and one dialog (`WorktreeRemoveDialog.vue`) serve every entry point.

**Tech Stack:** Rust (Tauri 2), Vue 3 `<script setup>`, Vitest, dev-server.mjs.

**Spec:** `docs/superpowers/specs/2026-11-04-v3.13-agent-workspaces-i-design.md` §7, §8, §9 (metadata only), §10.1, §12 item 4.

## Global Constraints

- `safe_repo_path` on every user-supplied path; git through argument arrays only (`AGENTS.md`).
- Each new `#[tauri::command]`: wrapper in `utils/backend.ts`, entry in `utils/commandRegistry.ts`, dev-server route.
- Every user-visible string in the 5 locales.
- Real git repos in tests. `cargo fmt` and `cargo clippy -D warnings` before pushing (CI runs Rust 1.99).
- GitWand never deletes a `.worktree-keep` file; `git worktree remove` is never passed `--force` twice.
- Hooks never run for worktrees GitWand does not own (§11).

## Decisions (rulings made while planning)

- **Prepare / finish split.** Spec §10.1 has one `worktree_remove` taking the teardown exit code, which would put the snapshot *after* teardown. A teardown may delete files (or the whole worktree), so the snapshot must come first (§7.2 order). `worktree_remove_prepare` runs steps 1–3, `worktree_remove` steps 1 (again) and 5–7. Cost if wrong: one extra command.
- **Snapshot always taken on removal**, whatever the `snapshotsEnabled` setting: it is what makes `--force` safe (§7.2 step 5). Without a snapshot (no `HEAD`), no `--force`.
- **Teardown is required only for worktrees that have a record** (created by the service, which is the only path that offers setup). Legacy `gitwand-scratch-*` worktrees are owned but never ran setup.
- **Owned** = a record in `worktrees.json`, or a legacy `gitwand-scratch-*` basename, or a legacy `branch.<b>.gitwandBase` config.
- **Other-tool directories** (one constant): consecutive path components `.claude/worktrees`, `conductor/workspaces`, `.superset/worktrees`.
- **Merged** (step 6) = the branch is an ancestor of the record's source branch, else of the main worktree's `HEAD`.
- **Merge-back cleanup.** `scratch_worktree_merge_back` gets `cleanup: Option<bool>` (default `true`). The AI-task flow passes `false` and runs the shared removal flow right after, so teardown runs. Merge-back and discard refuse an untouchable worktree up front; discard refuses a recorded worktree whose repo defines teardown (it has no teardown result to give).
- **`git_worktree_remove`** stays (compatibility) but refuses an untouchable worktree.
- **Unlock**: new `worktree_unlock(cwd, path)`, the only action offered on a git-locked worktree.

## Review Focus

1. A teardown that deletes the worktree directory itself: `worktree_remove` must still prune, drop the branch and the record.
2. A locked worktree reached from every entry point (manager, AI-task close, Git Tree, merge-back, discard): refused, nothing changed.
3. A foreign process with its cwd in the worktree after prepare: `worktree_remove` refuses, even if the frontend skipped the survivors screen.
4. The trust prompt answered "Skip hooks this time": removal goes through, the dialog says teardown did not run.
5. A task branch not merged and "Also delete branch" unticked: the branch survives.
