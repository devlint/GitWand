# v3.13 PR 1 — Worktree config & hook trust Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `.gitwandrc` accepts a validated `worktree` section, `.worktreeinclude` can be parsed, and GitWand can ask for and remember the user's trust in a repo's `setup` / `teardown` / `url` commands. Nothing runs the hooks yet; that is PR 3.

**Architecture:**
- The schema and the include parser live in `@gitwand/core` (pure TypeScript, browser-safe).
- The trust store lives in Rust, so that the commands of later PRs can enforce it:
  - The hooks are always read from the **main worktree's** config.
  - Their hash is computed on the backend.
  - The trust is stored in `{data_local_dir}/gitwand/hook-trust.json`.
- A frontend composable and a modal ask the question. The modal is mounted in `App.vue`; its call sites arrive in PR 3 and PR 4.

**Tech Stack:** TypeScript (vitest), Rust (Tauri 2, `serde_json`, `sha2`, `dirs`), Vue 3 `<script setup>`, Node dev-server (`node:crypto`).

**Spec:** `docs/superpowers/specs/2026-11-04-v3.13-agent-workspaces-i-design.md` (§4, §10.1 `worktree_hooks_trust*`, §12 item 1)

## Global Constraints

- `packages/core` gets no Node module (`fs`, `path`, `crypto`…).
- `.gitwandrc` stays JSON. Unknown or invalid `worktree` entries are dropped, never fatal.
- The hooks are read from the main worktree, never from a linked worktree's copy (spec §4, "Which copy is read").
- The trust is keyed per repo (the canonical main worktree root) and holds the SHA-256 of the canonical JSON of `{setup, teardown, url}`. Any change to the strings asks again. The trust is stored in app data, never in the repo.
- `include` needs no trust.
- Every Tauri command:
  - is called through `utils/backend.ts`;
  - has a `utils/commandRegistry.ts` entry;
  - has a dev-server route;
  - passes `cwd` through `safe_repo_path`.
- Every user-visible string goes into all 5 locales (`en`, `fr`, `es`, `pt-BR`, `zh-CN`).
- Before pushing Rust, run `cargo fmt`.

## Review Focus

1. **The hooks change between the dialog being shown and "Trust" being clicked.** Trust must not be recorded for strings the user never saw. → Task 3, `trust_set_refuses_stale_hash`.
2. **The repo is opened from a linked worktree whose `.gitwandrc` was edited by an agent.** The status must show the main worktree's hooks. → Task 3, `status_reads_main_worktree_config`.
3. **The trust store is missing, empty, or contains invalid JSON.** It is treated as empty, and the next trust rewrites it. → Task 2, `load_store_tolerates_corrupt_file`.
4. **The same repo is reached through two paths** (macOS `/var` → `/private/var`, a symlinked checkout). It must have a single trust entry. → Task 3, `status_key_is_canonical_root`.
5. **The Rust and dev-server hashes disagree** on quotes, newlines or non-ASCII. Manual QA in `dev:web` would then pass where the app would ask again. → Task 2 and Task 4 share one fixed test vector.

**Interfaces:**
- Consumes: `worktreeHooksTrust` and `worktreeHooksTrustSet` from `utils/backend.ts` (Task 3).
- Produces (used by PR 3 for creation and PR 4 for removal):
  ```ts
  export type HookTrustChoice = "run" | "skip" | "cancel";
  export function useWorktreeHookTrust(): {
    pending: Readonly<Ref<HookTrustStatus | null>>;   // non-null while the modal is open
    error: Readonly<Ref<string | null>>;              // e.g. the stale-hash message
    ensureTrusted(cwd: string): Promise<HookTrustChoice>;
    answer(choice: "trust" | "skip" | "cancel"): Promise<void>;
  };
  ```
  The state is a module-level singleton, so the call sites and the mounted modal share it.

Semantics:
- `ensureTrusted` returns `"run"` immediately when `status.trusted`, without opening anything.
- Otherwise it sets `pending` and resolves when `answer` is called:
  - `"trust"` calls `worktreeHooksTrustSet(cwd, pending.hash)`, then resolves `"run"`. If that call fails (stale hash), it sets `error`, re-reads the status into `pending` and keeps the modal open, so the user sees the new strings and answers again.
  - `"skip"` resolves `"skip"`.
  - `"cancel"` resolves `"cancel"`.
- A second `ensureTrusted` while one is pending returns `"cancel"`.

Modal:
- It uses `BaseModal`.
- Title and intro text:
  - `worktreeHooks.title` = "Run this repository's worktree commands?"
  - `worktreeHooks.intro` = "This repository defines commands that GitWand runs when it creates or removes a worktree. They run with your permissions. Only trust them if you trust this repository."
- One `<pre>` per non-null hook, labeled `worktreeHooks.setup` / `.teardown` / `.url` ("Setup" / "Teardown" / "URL"). The command is shown as text interpolation, never as HTML.
- Buttons:
  - `worktreeHooks.trust` = "Trust and run" (`bm-btn--primary`)
  - `worktreeHooks.skip` = "Skip commands this time"
  - `worktreeHooks.cancel` = "Cancel"
- Below the commands: `worktreeHooks.changedNote` = "GitWand will ask again if these commands change."
- `error` is shown above the buttons when set.
