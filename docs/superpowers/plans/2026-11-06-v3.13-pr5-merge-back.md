# v3.13 PR 5 — Merge-back Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** an AI task (or any GitWand-owned worktree) comes back as real commits, through the v3.11 preview → apply flow, in three modes: merge (default), rebase, squash (spec §6).

**Architecture:** a read-only check and a preparation step in a new Rust module `worktree/merge_back.rs`; the preview and the apply reuse `useMergePreview` / `MergePreviewPanel` / `useApplyFromPreview`; two small runners for what git primitives do not cover yet (`merge --squash`, the final `merge --ff-only`). One frontend state machine (`useWorktreeMergeBack.ts`) and one dialog (`MergeBackDialog.vue`).

**Spec:** `docs/superpowers/specs/2026-11-04-v3.13-agent-workspaces-i-design.md` §6, §10.1, §12 item 5.

## Global Constraints

Same as PR 4: `safe_repo_path`, git argument arrays, backend.ts + commandRegistry + dev-server route per command, 5 locales, real git repos in tests, `cargo fmt` + `clippy -D warnings`.

## Decisions

- **Check and prepare are two commands.** `worktree_merge_back_check(cwd, path, target?)` is read-only (§6.1 steps 1–2) and feeds the dialog, including the "switch the main checkout" offer. `worktree_merge_back_prepare(cwd, path, target)` re-runs the check, then steps 3–5. Spec §10.1 names only prepare.
- **Default target:** the record's source branch, else the legacy `branch.<b>.gitwandSource`, else the local branch of the recorded base (`origin/main` → `main`), else the main checkout's branch.
- **Overlap** = the main checkout's changed or untracked paths ∩ (the task's committed changes since the merge base with the target ∪ its uncommitted paths).
- **Snapshots are always taken** (as for removal), whatever `snapshotsEnabled` says.
- **One `useApplyFromPreview` instance, bound to the open checkout.** Spec §6.2 asks for one per checkout; §6.2 also says GitWand focuses the checkout being operated on. Focusing it first and running the existing instance there satisfies both with the dependencies it already has. `apply` gains `opts.runMerge` (merge-back's own runner: `--no-ff --no-edit`, or `--squash`) and `opts.skipFinalize` (a squash has no `--continue`).
- **Squash runner:** `worktree_merge_back_squash` runs `git merge --squash --no-autostash --no-verify-signatures <task>` in the main checkout; conflicts are a result, not an error.
- **Rebase finish:** `worktree_merge_back_fast_forward` runs `git merge --ff-only --no-autostash <task>` in the main checkout, refusing while the task's rebase is still in progress.
- **Cleanup is offered, never automatic** (§6.1 step 8). Merge/rebase: the branch is merged, so the removal service deletes it. Squash: the dialog explains it is not merged and the removal dialog asks (box unticked).
- **Conflict-scratch merge-back** (`scratch_worktree_merge_back`, "Resolve in scratch") is unchanged; only the AI-task flow moves.

## Tasks

1. **Rust `worktree/merge_back.rs`:** `check`, `prepare`, `squash`, `fast_forward`. Tests (real repos): default target from record; wrong branch (with `main_clean`); main mid-merge; overlap refused / unrelated change allowed; nothing to bring back; prepare commits WIP as `wip(<name>): uncommitted work at merge-back` without hooks, snapshots both sides (`merge-back-task` with worktree metadata, `merge-back`); prepare refuses on survivors; squash with a conflict leaves stages; fast-forward refuses mid-rebase, then fast-forwards.
2. **Commands + registration + dev-server mirror + parity for `worktree_merge_back_check`.**
3. **`useApplyFromPreview` options** (`runMerge`, `skipFinalize`) with tests.
4. **`useWorktreeMergeBack.ts`** state machine with injected deps and tests: refusal → switch → recheck; survivors; preview ref/cwd per mode; apply clean → done; rebase clean → fast-forward → done; residual → resume; cleanup request carries `deleteBranch` (squash: false).
5. **`MergeBackDialog.vue`**, App wiring (host registration: focus checkout + apply), AI-task "Merge back" and worktree manager "Merge back" entry points, locales ×5, CHANGELOG.
6. Full suites, fresh review, fixes, PR.
