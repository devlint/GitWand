# v3.10.0 Live Repo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make GitWand reactive (filesystem events replace the 2s status poll) and faster (libgit2 fast paths for diff/blame, conflict engine off the main thread, scoped progress channels).

**Architecture:** A per-repo `notify` watcher in the Rust backend coalesces raw FS events into a small typed `RepoChangeEvent` and fans it out to N subscribers over `tauri::ipc::Channel`. The frontend `useRepoWatcher` composable turns those events into invalidation calls; `useRepoPoller` demotes itself to a slow fallback whenever a watcher is healthy. Three independent perf slices ride along: libgit2 fast paths for `git_diff`/`git_blame` (patch text generated in-process, then fed to the existing parser so the output shape is identical), `tauri::ipc::Channel` for clone/fetch progress, and a Comlink Web Worker hosting `@gitwand/core` so the pattern registry and tree-sitter never touch the main thread.

**Tech Stack:** Rust (Tauri 2, `notify`, `git2`), Vue 3 Composition API, TypeScript, Comlink, Vitest, Node dev-server (`dev-server.mjs`).

# Phase A: FS Watcher Backend

**Goal:** A per-repo filesystem watcher in Rust that coalesces raw events into typed `RepoChangeEvent`s and streams them to any number of subscribers over `tauri::ipc::Channel`, with a working `dev-server.mjs` SSE equivalent. No frontend behavior changes yet.

**Design notes:**
- One OS watcher per canonical repo path, shared by N subscribers. This is the "indexing hook" requirement from the roadmap: the v4.0 code-graph indexer will call `watch_repo_start` on the same path and get its own `Channel` without a second `notify` watcher.
- Event payload carries changed **worktree-relative paths**, capped, with a `truncated` flag. That is what an incremental re-indexer needs; a status refresh only needs `kinds`.
- Debounce/coalesce in our own thread (150 ms quiet window). We deliberately do **not** add `notify-debouncer-full`: one dependency is enough, and we need custom classification anyway.

**File Structure:**

| File | Responsibility |
|---|---|
| `apps/desktop/src-tauri/src/commands/watcher.rs` (create) | `classify_path()` pure fn, watcher registry, `watch_repo_start` / `watch_repo_stop` commands |

| `apps/desktop/src-tauri/src/lib.rs` (modify) | register the 2 new commands in `generate_handler!` |

| Input prefix | Returns |
|---|---|
| `.git/HEAD` | `Some("head")` |
| `.git/index` | `Some("index")` |
| `.git/refs/...`, `.git/packed-refs` | `Some("refs")` |
| `.git/config` | `Some("config")` |
| `.git/MERGE_HEAD`, `REBASE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `.git/rebase-merge/...`, `.git/rebase-apply/...`, `.git/MERGE_MSG` | `Some("mergeState")` |
| `.git/refs/stash`, `.git/logs/refs/stash` | `Some("stash")` |
| `.git/objects/...`, `.git/lfs/...`, `.git/index.lock`, any path ending in `.lock` under `.git/`, `.git/logs/...` (other than stash) | `None` (ignored: pure noise) |
| any other `.git/...` | `None` |
| `node_modules/...`, `target/...`, `dist/...`, `.venv/...`, `__pycache__/...` anywhere in the path | `None` |
| anything else | `Some("worktree")` |

Order matters: check `stash` before the generic `refs` rule, and check the ignore list before `worktree`.

```rust
/// Directory names whose contents are never interesting, at any depth.
const IGNORED_DIRS: [&str; 5] = ["node_modules", "target", "dist", ".venv", "__pycache__"];

pub(crate) fn classify_path(rel: &str) -> Option<&'static str> {
    let rel = rel.trim_start_matches("./");

    if let Some(inner) = rel.strip_prefix(".git/") {
        // Noise first: object churn, transient locks, reflogs.
        if inner.starts_with("objects/") || inner.starts_with("lfs/") || inner.ends_with(".lock") {
            return None;
        }
        // Stash lives under refs/ and logs/refs/, so it must be tested before
        // the generic refs rule below and before the logs/ ignore.
        if inner == "refs/stash" || inner == "logs/refs/stash" {
            return Some("stash");
        }
        if inner.starts_with("logs/") {
            return None;
        }
        if inner == "HEAD" {
            return Some("head");
        }
        if inner == "index" {
            return Some("index");
        }
        if inner == "config" {
            return Some("config");
        }
        if inner.starts_with("refs/") || inner == "packed-refs" {
            return Some("refs");
        }
        if matches!(
            inner,
            "MERGE_HEAD" | "REBASE_HEAD" | "CHERRY_PICK_HEAD" | "REVERT_HEAD" | "MERGE_MSG"
        ) || inner.starts_with("rebase-merge/")
            || inner.starts_with("rebase-apply/")
        {
            return Some("mergeState");
        }
        return None;
    }

    if rel.split('/').any(|seg| IGNORED_DIRS.contains(&seg)) {
        return None;
    }
    if rel.is_empty() {
        return None;
    }
    Some("worktree")
}
```

```rust
/// Turn a raw batch of repo-relative paths into one event, or `None` when
/// nothing in the batch is interesting. Paths and kinds are deduplicated and
/// sorted so the payload is deterministic (and so tests are stable).
pub(crate) fn coalesce(batch: &[String]) -> Option<RepoChangeEvent> {
    let mut kinds = std::collections::BTreeSet::<&'static str>::new();
    let mut paths = std::collections::BTreeSet::<String>::new();
    for p in batch {
        if let Some(kind) = classify_path(p) {
            kinds.insert(kind);
            paths.insert(p.clone());
        }
    }
    if kinds.is_empty() {
        return None;
    }
    let truncated = paths.len() > EVENT_PATH_CAP;
    Some(RepoChangeEvent {
        kinds: kinds.into_iter().map(str::to_string).collect(),
        paths: paths.into_iter().take(EVENT_PATH_CAP).collect(),
        truncated,
    })
}
```

```rust
use std::collections::HashMap;
use std::path::PathBuf;
use std::sync::atomic::{AtomicBool, AtomicU64, Ordering};
use std::sync::{mpsc, Arc, Mutex, OnceLock};
use std::time::Duration;

use notify::{RecommendedWatcher, RecursiveMode, Watcher};
use tauri::ipc::Channel;

use crate::git::safe_repo_path;

/// Quiet window before a batch is flushed. Long enough to swallow the dozens of
/// events a single `git checkout` produces, short enough to feel instant.
const DEBOUNCE: Duration = Duration::from_millis(150);

struct RepoWatch {
    /// Dropping the watcher stops the OS-level subscription.
    _watcher: RecommendedWatcher,
    stop: Arc<AtomicBool>,
    subscriber_count: usize,
}

fn watches() -> &'static Mutex<HashMap<PathBuf, RepoWatch>> {
    static W: OnceLock<Mutex<HashMap<PathBuf, RepoWatch>>> = OnceLock::new();
    W.get_or_init(|| Mutex::new(HashMap::new()))
}

type Subscribers = HashMap<u64, (PathBuf, Channel<RepoChangeEvent>)>;

fn subscribers() -> &'static Mutex<Subscribers> {
    static S: OnceLock<Mutex<Subscribers>> = OnceLock::new();
    S.get_or_init(|| Mutex::new(HashMap::new()))
}

fn lock_watches() -> std::sync::MutexGuard<'static, HashMap<PathBuf, RepoWatch>> {
    watches().lock().unwrap_or_else(|e| e.into_inner())
}

fn lock_subscribers() -> std::sync::MutexGuard<'static, Subscribers> {
    subscribers().lock().unwrap_or_else(|e| e.into_inner())
}

static NEXT_ID: AtomicU64 = AtomicU64::new(1);

/// Fan an event out to every live subscriber of `root`.
fn broadcast(root: &PathBuf, event: &RepoChangeEvent) {
    let subs = lock_subscribers();
    for (path, chan) in subs.values() {
        if path == root {
            // A dead channel (window closed) just errors; the subscription is
            // reaped by watch_repo_stop or by the next app_handle teardown.
            let _ = chan.send(event.clone());
        }
    }
}

/// Start (or join) a watch on `cwd`. Returns a subscription id to pass to
/// `watch_repo_stop`. Calling this twice on the same repo creates two
/// independent subscriptions sharing a single OS watcher: this is the
/// extension point the v4.0 incremental code-graph indexer will use.
#[tauri::command]
pub(crate) fn watch_repo_start(
    cwd: String,
    on_change: Channel<RepoChangeEvent>,
) -> Result<u64, String> {
    let root = safe_repo_path(cwd.trim(), ".").map_err(|e| format!("invalid cwd: {e}"))?;
    if !root.is_dir() {
        return Err("cwd is not a directory".to_string());
    }

    let id = NEXT_ID.fetch_add(1, Ordering::Relaxed);
    lock_subscribers().insert(id, (root.clone(), on_change));

    let mut watches = lock_watches();
    if let Some(existing) = watches.get_mut(&root) {
        existing.subscriber_count += 1;
        return Ok(id);
    }

    let (tx, rx) = mpsc::channel::<notify::Result<notify::Event>>();
    let mut watcher = notify::recommended_watcher(move |res| {
        let _ = tx.send(res);
    })
    .map_err(|e| format!("failed to create watcher: {e}"))?;
    watcher
        .watch(&root, RecursiveMode::Recursive)
        .map_err(|e| format!("failed to watch {}: {e}", root.display()))?;

    let stop = Arc::new(AtomicBool::new(false));
    let thread_root = root.clone();
    let thread_stop = stop.clone();
    std::thread::spawn(move || {
        let mut batch: Vec<String> = Vec::new();
        loop {
            if thread_stop.load(Ordering::Relaxed) {
                return;
            }
            match rx.recv_timeout(DEBOUNCE) {
                Ok(Ok(event)) => {
                    for p in event.paths {
                        if let Ok(rel) = p.strip_prefix(&thread_root) {
                            let rel = rel.to_string_lossy().replace('\\', "/");
                            if !rel.is_empty() {
                                batch.push(rel);
                            }
                        }
                    }
                }
                // A watcher error (e.g. inotify queue overflow) must not kill
                // the loop: force a "everything changed" event so the UI
                // resyncs, then keep going.
                Ok(Err(_)) => {
                    broadcast(
                        &thread_root,
                        &RepoChangeEvent {
                            kinds: vec!["worktree".to_string()],
                            paths: Vec::new(),
                            truncated: true,
                        },
                    );
                    batch.clear();
                }
                Err(mpsc::RecvTimeoutError::Timeout) => {
                    if !batch.is_empty() {
                        if let Some(ev) = coalesce(&batch) {
                            broadcast(&thread_root, &ev);
                        }
                        batch.clear();
                    }
                }
                Err(mpsc::RecvTimeoutError::Disconnected) => return,
            }
        }
    });

    watches.insert(
        root,
        RepoWatch {
            _watcher: watcher,
            stop,
            subscriber_count: 1,
        },
    );
    Ok(id)
}

/// Drop a subscription. When the last subscriber for a repo leaves, the OS
/// watcher and its coalescing thread are torn down.
#[tauri::command]
pub(crate) fn watch_repo_stop(id: u64) -> Result<(), String> {
```

```typescript
/**
 * useRepoWatcher - Live Repo filesystem subscription (v3.10.0).
 *
 * Owns exactly one backend watch subscription for the active repo and fans
 * coalesced change events out to registered handlers. `healthy` drives the
 * poll demotion in useRepoPoller: when this is false (watcher unsupported,
 * network mount, backend error) the poller stays on its fast cadence.
 */
import { onUnmounted, ref, type Ref } from "vue";
import { watchRepoStart, watchRepoStop, type RepoChangeEvent } from "../utils/backend";

export type RepoChangeKind =
  | "head" | "index" | "refs" | "config" | "mergeState" | "stash" | "worktree";

export interface RepoWatcherApi {
  healthy: Ref<boolean>;
  setFolderPath: (path: string | null) => void;
  on: (kinds: RepoChangeKind[], handler: (ev: RepoChangeEvent) => void) => () => void;
}

interface Registration {
  kinds: Set<string>;
  handler: (ev: RepoChangeEvent) => void;
}

export function useRepoWatcher(opts?: { onHealthChange?: (healthy: boolean) => void }): RepoWatcherApi {
  const healthy = ref(false);
  const registrations = new Set<Registration>();

  let _folderPath: string | null = null;
  let _subscriptionId: number | null = null;
  /** Guards against a slow start() resolving after the folder already changed. */
  let _generation = 0;

  function setHealthy(value: boolean) {
    if (healthy.value === value) return;
    healthy.value = value;
    opts?.onHealthChange?.(value);
  }

  function dispatch(ev: RepoChangeEvent) {
    for (const reg of registrations) {
      const matches = ev.truncated || ev.kinds.some((k) => reg.kinds.has(k));
      if (!matches) continue;
      try {
        reg.handler(ev);
      } catch (err) {
        console.warn("[gitwand] repo watcher handler threw", err);
      }
    }
  }

  async function stop() {
    const id = _subscriptionId;
    _subscriptionId = null;
    setHealthy(false);
    if (id !== null) {
      try { await watchRepoStop(id); } catch { /* teardown is best-effort */ }
    }
  }

  function setFolderPath(path: string | null) {
    if (path === _folderPath) return;
    _folderPath = path;
    const generation = ++_generation;
    void stop().then(async () => {
      if (!path || generation !== _generation) return;
      try {
        const id = await watchRepoStart(path, dispatch);
        if (generation !== _generation) {
          // The folder changed while start() was in flight: drop this one.
          void watchRepoStop(id);
          return;
        }
        _subscriptionId = id;
        setHealthy(true);
      } catch (err) {
        console.warn("[gitwand] filesystem watcher unavailable, staying on poll fallback", err);
        setHealthy(false);
      }
    });
  }

  function on(kinds: RepoChangeKind[], handler: (ev: RepoChangeEvent) => void): () => void {
    const reg: Registration = { kinds: new Set<string>(kinds), handler };
    registrations.add(reg);
    return () => { registrations.delete(reg); };
  }

  onUnmounted(() => { void stop(); });

  return { healthy, setFolderPath, on };
}
```

```typescript
// Serialize watcher-driven refreshes: an `rm -rf node_modules` or a branch
// switch produces several coalesced batches back to back, and without this a
// burst would stack concurrent repoRefresh() calls on the same repo.
let _wtRefreshInFlight: Promise<void> | null = null;
let _wtRefreshQueued = false;

function scheduleWatcherRefresh(run: () => Promise<void>) {
  if (document.hidden) return;
  if (_wtRefreshInFlight) {
    _wtRefreshQueued = true;
    return;
  }
  _wtRefreshInFlight = run()
    .catch(() => {})
    .finally(() => {
      _wtRefreshInFlight = null;
      if (_wtRefreshQueued) {
        _wtRefreshQueued = false;
        scheduleWatcherRefresh(run);
      }
    });
}

repoWatcher.on(["worktree", "index"], () => {
  scheduleWatcherRefresh(async () => {
    await repoRefresh();
    if (viewMode.value === "history" || showGitTree.value) await loadLog();
```

```rust
/// Render `git diff [--cached] -- <path>` as unified-diff text, in process.
///
/// Deliberately produces *text* rather than `DiffHunk`s: the caller feeds it to
/// the same `parse_diff_hunks` the CLI output goes through, so the two paths
/// cannot drift in hunk shaping, line classification, or the leading-space
/// context-line rule (AGENTS.md "Diff Parsing").
pub(crate) fn libgit2_diff_patch(cwd: &str, path: &str, staged: bool) -> Result<String, String> {
    let repo = git2::Repository::open(cwd).map_err(|e| format!("git2 open: {e}"))?;

    let mut opts = git2::DiffOptions::new();
    opts.pathspec(path);
    // Match the CLI defaults `git diff` uses for the UI: 3 lines of context,
    // no rename detection on a single-path diff.
    opts.context_lines(3);
    opts.include_untracked(false);

    let diff = if staged {
        // HEAD tree to index. An unborn HEAD has no tree: diff against nothing.
        let head_tree = match repo.head().ok().and_then(|h| h.peel_to_tree().ok()) {
            Some(t) => Some(t),
            None => None,
        };
        repo.diff_tree_to_index(head_tree.as_ref(), None, Some(&mut opts))
            .map_err(|e| format!("git2 diff_tree_to_index: {e}"))?
    } else {
        repo.diff_index_to_workdir(None, Some(&mut opts))
            .map_err(|e| format!("git2 diff_index_to_workdir: {e}"))?
    };

    let mut out = String::new();
    diff.print(git2::DiffFormat::Patch, |_delta, _hunk, line| {
        match line.origin() {
            // Content lines carry their origin char separately from the text.
            '+' | '-' | ' ' => out.push(line.origin()),
            _ => {}
        }
        out.push_str(&String::from_utf8_lossy(line.content()));
        true
    })
    .map_err(|e| format!("git2 diff print: {e}"))?;

    Ok(out)
}
```

The match above does exactly that. If a `\ No newline at end of file` line differs, note that its origin is `>` or `<`; emit its content unprefixed too (already handled by the `_ => {}` arm).

```rust
) -> Result<Vec<BlameLine>, String> {
    let repo = git2::Repository::open(cwd).map_err(|e| format!("git2 open: {e}"))?;
    let blame = repo
        .blame_file(std::path::Path::new(path), None)
        .map_err(|e| format!("git2 blame: {e}"))?;

    let workdir = repo.workdir().ok_or_else(|| "bare repository".to_string())?;
    let content = std::fs::read_to_string(workdir.join(path))
        .map_err(|e| format!("failed to read {path}: {e}"))?;
    let file_lines: Vec<&str> = content.split('\n').collect();

    // One commit lookup per distinct OID, not per line.
    let mut meta: std::collections::HashMap<git2::Oid, (String, String, String)> =
        std::collections::HashMap::new();

    let mut out: Vec<BlameLine> = Vec::new();
    for hunk in blame.iter() {
        let oid = hunk.final_commit_id();
        let (author, author_date, summary) = meta
            .entry(oid)
            .or_insert_with(|| match repo.find_commit(oid) {
                Ok(c) => (
                    c.author().name().unwrap_or("").to_string(),
                    // The CLI path stores git's raw `author-time` epoch seconds
                    // as a string (commands/read.rs). Match it exactly.
                    c.author().when().seconds().to_string(),
                    c.summary().unwrap_or("").to_string(),
                ),
                Err(_) => (String::new(), String::new(), String::new()),
            })
            .clone();

        let hash_full = oid.to_string();
        let hash = hash_full[..7].to_string();
        let start = hunk.final_start_line();
        let orig_start = hunk.orig_start_line();
        for i in 0..hunk.lines_in_hunk() {
            if out.len() >= max_entries {
                return Ok(out);
            }
            let final_line = (start + i) as u32;
            out.push(BlameLine {
                hash: hash.clone(),
                hash_full: hash_full.clone(),
                final_line,
                orig_line: (orig_start + i) as u32,
                author: author.clone(),
                author_date: author_date.clone(),
                summary: summary.clone(),
                content: file_lines
                    .get(final_line as usize - 1)
                    .map(|s| s.to_string())
                    .unwrap_or_default(),
            });
        }
    }
    Ok(out)
}
```

# Phase F: Web Worker for the Core Diff/Parse Hot Path

**Goal:** Run `@gitwand/core`'s `resolve` / `resolveAsync` / `parseConflictMarkers` in a Web Worker via Comlink, so the pattern registry and tree-sitter never execute on the main thread.

**Depends on:** nothing.

**The choke point that makes this tractable:** every heavy core call in the app already goes through one memoized loader, `engine()` in `apps/desktop/src/utils/coreEngine.ts`. There are exactly 11 call sites (`useGitWand.ts` x10, `useMergePreview.ts` x1). No change to `packages/core` is needed or permitted.

**Two constraints that shape the design:**
1. **`resolve` becomes async.** Nine call sites currently do `const { resolve } = await engine(); ... resolve(x)` synchronously. Two of them are inside a synchronous `.map()` (`useGitWand.ts:718` and `:737`) and must become `Promise.all(map(async ...))`.
2. **The LLM endpoint cannot cross into the worker as data.** `resolveOptionsWithLlm.llmFallback.endpoint` is a function produced by `ai.toLlmEndpoint()` (`useGitWand.ts:480`), and it calls the AI provider through `backend.ts`, which needs `window.__TAURI_INTERNALS__`. That is unavailable in a worker. The endpoint must be passed as `Comlink.proxy(endpoint)` so calls hop back to the main thread. Same for nothing else: `structuralOpts.customLoader` is rebuilt **inside** the worker (a worker can `fetch('/grammars/...')` directly), so it never crosses the boundary.

```typescript
/**
 * Facade over the `@gitwand/core` conflict-resolution engine.
 *
 * v3.10.0: the engine runs in a Web Worker (`../workers/coreEngine.worker.ts`)
 * so the pattern registry, the classifier and tree-sitter never execute on the
 * main thread. Every method is async, including `resolve`, which used to be
 * synchronous once the module was loaded.
 *
 * Callers keep the same entry point they had when this file was a lazy module
 * loader: the dynamic-import boundary that keeps ~244 KB out of the boot chunk
 * is preserved, it just moved into the worker.
 *
 * Fallback: environments without `Worker` (Vitest's `node` environment, SSR)
 * transparently get an in-thread implementation with identical signatures, so
 * unit tests and any non-browser consumer keep working.
 */
import * as Comlink from "comlink";
import type { GitWandOptions, MergeResult } from "@gitwand/core";
import type { CoreEngineWorkerApi } from "../workers/coreEngine.worker";

export interface CoreEngineFacade {
  resolve(content: string, filePath: string, options?: GitWandOptions): Promise<MergeResult>;
  resolveAsync(content: string, filePath: string, options?: GitWandOptions): Promise<MergeResult>;
  parseConflictMarkers(
    content: string,
  ): Promise<Awaited<ReturnType<CoreEngineWorkerApi["parseConflictMarkers"]>>>;
}

let _facade: Promise<CoreEngineFacade> | null = null;

/** Same grammar loader the worker uses, for the in-thread fallback. */
const structuralOpts = {
  wasmPath: "/grammars/web-tree-sitter.wasm",
  customLoader: async (grammarName: string): Promise<Uint8Array> => {
    const response = await fetch(`/grammars/${grammarName}.wasm`);
    if (!response.ok) {
      throw new Error(`[gitwand] Failed to fetch grammar ${grammarName} (HTTP ${response.status})`);
    }
    return new Uint8Array(await response.arrayBuffer());
  },
};

async function inThreadFacade(): Promise<CoreEngineFacade> {
  const core = await import("@gitwand/core");
  return {
    async resolve(content, filePath, options) {
      return core.resolve(content, filePath, options as never);
    },
    async resolveAsync(content, filePath, options) {
      return core.resolveAsync(content, filePath, options as never, structuralOpts);
    },
    async parseConflictMarkers(content) {
      return core.parseConflictMarkers(content) as never;
    },
  };
}

async function workerFacade(): Promise<CoreEngineFacade> {
  const worker = new Worker(new URL("../workers/coreEngine.worker.ts", import.meta.url), {
    type: "module",
  });
  return Comlink.wrap<CoreEngineWorkerApi>(worker) as unknown as CoreEngineFacade;
}

export function engine(): Promise<CoreEngineFacade> {
  return (_facade ??= (async () => {
    if (typeof Worker === "undefined") return inThreadFacade();
    try {
      return await workerFacade();
    } catch (err) {
      console.warn("[gitwand] core engine worker unavailable, running in-thread", err);
      return inThreadFacade();
    }
  })());
}
```

**Post-verification fixes (2026-09-01, verifier findings):**

1. **`Comlink.proxy()` doesn't survive nesting inside `options`.** The plan's original Task F3 step 1 wrote `llmFallback: { ...llmCfg, endpoint: Comlink.proxy(aiEndpoint) }` — a proxy marker nested three levels inside the `options` argument passed to `resolveAsync`. Comlink only recognizes a `Comlink.proxy()` marker on a **top-level** RPC argument (`processArguments` in `comlink.mjs` maps `toWireValue` over each argument in `argumentList`, with no recursion into an argument's own properties), so this nested marker was silently ignored and the live `endpoint.call` function inside `options` tripped `postMessage`'s structured-clone algorithm: `DataCloneError: ... could not be cloned`, reproduced against the real worker in headless Chrome. Fixed by giving `resolveAsync` a dedicated 4th top-level parameter, `endpointProxy?: LlmEndpoint` (worker: `coreEngine.worker.ts`; facade: `coreEngine.ts`), which the worker splices into `options.llmFallback.endpoint` itself before calling `@gitwand/core`. Callers build `options` with `llmFallback` carrying no `endpoint` at all, and pass `Comlink.proxy(aiEndpoint)` as the separate top-level argument instead.

2. **`resolveOptions.value` is a Vue reactive Proxy, and V8's structured-clone rejects a JSProxy outright.** `resolveOptions` (`useGitWand.ts`) is a `ref<GitWandOptions>`, so `.value` — and any nested object property read through it (`patternOverrides`/`generatedFiles`, set from `.gitwandrc` parsing) — is a reactive Proxy at the point it's read, unrelated to the LLM-endpoint bug above but hitting the same underlying constraint (a live JS Proxy can't cross `postMessage`). A shallow spread of the reactive `.value` does not fix this: spreading only copies through the parent Proxy's `get` trap, which still returns a nested reactive Proxy for any object-valued property. Fixed by unwrapping at the source with Vue's `toRaw()` — `toRaw(resolveOptions.value)` — at every one of the 9 `core.resolve(...)` call sites in `useGitWand.ts` and in the `resolveOptionsWithLlm` spread, rather than trying to unwrap once inside the facade or worker (by the time a plain object has been built via spread, the nested reactive references are already copied in by reference — `toRaw()` on that result does nothing). Verified against a real `Vue.ref()` with a nested object property in headless Chrome: the unfixed pattern reproduces the exact `DataCloneError`, `toRaw()` eliminates it.

3. **A worker that fails to *load* hangs every call forever, with no error surfaced.** Comlink's RPC has no timeout. `engine()` only fell back to the in-thread facade when `typeof Worker === "undefined"` or the `new Worker(...)` constructor threw synchronously — a module chunk that fails to load (404, or a WebView without module-worker support) instead fires an async `error` event, by which point `engine()` has already handed callers a live reference to the (dead) worker facade. Added a `worker.addEventListener("error", ...)` handler in `coreEngine.ts`'s `workerFacade()` that terminates the worker and re-memoizes `_facade` to `inThreadFacade()`, so the conflict UI self-heals on the *next* call instead of staying frozen. Verified in headless Chrome by forcing the `coreEngine.worker` chunk to 404: the first call hangs (as expected — nothing can rescue an already in-flight RPC against a dead endpoint), the second call succeeds via the in-thread fallback.

**Known limitations, not fixed in this phase (low severity, follow-up candidates):**

- **Narrow worker-error race.** `workerFacade()` has no internal await before returning — `engine()` can hand a caller a live reference to the about-to-fail worker facade before the async `error` event has a chance to fire and demote `_facade`. If a worker chunk fails to load, the *first* conflict-load call in that window hangs indefinitely (per fix #3 above); only a subsequent retry gets the in-thread fallback. Exposure is small (requires a WebView without module-worker support, or a genuinely missing/corrupted chunk). Optional future fix: have `workerFacade()` await a cheap readiness probe (e.g. a round-trip `parseConflictMarkers("")` call) before returning, so load failures are caught before the facade is handed out at all.
- **New reentrancy window in `resolveAll`/`resolveFile`.** These used to run synchronously and atomically once the engine module was loaded; now that every call awaits a worker round-trip, two rapid user actions can race and one result can clobber another before the first resolves — there is no busy guard. Recoverable via the existing undo safety net (v3.8), but worth a dedicated busy-flag follow-up.

## Open Decisions (human checkpoint before execution)

1. **`notify` crate version and debouncing.** The plan uses raw `notify` with our own 150 ms coalescing thread and no `notify-debouncer-full`. Rationale: we need custom classification regardless, and one dependency is cheaper for compile time and binary size. Confirm, and confirm the major version `cargo add notify` resolves to (the API for `recommended_watcher` is stable across 6/7/8, but `RecursiveMode` import paths are worth double-checking against the resolved version).

2. **Watcher default state.** The plan ships `liveRepoWatcher: true` by default, with a Settings toggle to fall back to pure polling. The alternative is opt-in for one release. Recommendation: **on by default**, because the poll fallback is retained and the health signal auto-demotes on failure, so the blast radius is small.

3. **`git_blame` via libgit2 (the real risk in Phase D).** `git2::BlameOptions` has no `--diff-algorithm` knob, so libgit2 cannot honour the `blameAlgorithm` setting. The plan gates the fast path on the default (`histogram`) and makes Task D3 Step 4 a hard go/no-go: if libgit2's attribution differs from `git blame --diff-algorithm=histogram` on the fixture, blame stays on the CLI and libgit2 phase 1 ships as `git_diff` only. **Decide now whether you accept that fallback outcome**, or whether the phase should be defined as `git_diff` only from the start.

4. **Fetch progress UI.** `git_fetch` has no progress surface today. Task E2 adds a percentage in the status line for user-initiated fetches only (background fetches stay silent). Confirm that this is worth the new i18n key and the dev-server SSE route, or whether Phase E should be clone-only.

5. **Making `resolve()` async (Phase F).** 11 call sites change, two of which need `.map()` restructuring, and the LLM endpoint must cross the worker boundary as a `Comlink.proxy`. The alternative is worker-izing only the batch `loadRealFiles` path and leaving the nine single-hunk `resolve()` calls in-thread, which is a smaller diff but means tree-sitter and the pattern registry load **twice** (once per thread). Recommendation: **the full facade**, as planned. Confirm.

6. **Today Phase 3 forge scope.** The plan implements `nudge` for GitHub only (`ghPrCreateComment`), falling back to `open-pr` on GitLab / Azure / Bitbucket. `merge` reuses the existing per-forge merge path, so it is forge-agnostic already. Confirm GitHub-only nudge for this release, or ask for all four (`azPrCreateComment` exists; GitLab and Bitbucket need checking).

7. **Nudge comment copy.** `launchpad.nudge.comment` is currently `Friendly ping: this pull request is ready for review.` This is text that gets posted publicly under the user's name. Confirm the wording, or decide it should be user-editable in the confirm modal instead of a fixed string.

8. **Phase ordering.** The plan recommends A-B-C, then D/E/F in any order, then G. If you would rather ship a visible perf win first, D and F are both independent and could go before the watcher block.

## Decisions Made (2026-09-01, human checkpoint)

1. **`notify` version/debouncing** — go with the plan as written (raw `notify`, no `notify-debouncer-full`, custom 150ms coalescing). No change; executor verifies the resolved major version at `cargo add` time.
2. **Watcher default state** — **on by default**. Poll fallback + auto-demotion on failure keep the blast radius small.
3. **`git_blame` via libgit2** — **accept the fallback outcome**: if the fixture test shows libgit2's attribution diverges from `git blame --diff-algorithm=histogram`, `git_blame` stays on the CLI path and Phase D ships `git_diff` only. Do not force it.
4. **Fetch progress UI** — **include it** (not clone-only). Same Channels work as clone progress; closes a real UX gap.
5. **`resolve()` async (Phase F)** — **full facade**, all 11 call sites. Rejects the partial worker-ization to avoid double-loading tree-sitter/pattern registry per thread.
6. **Today Phase 3 forge scope** — **GitHub-only nudge** for this release (`open-pr` fallback elsewhere); `merge` stays forge-agnostic already. Non-GitHub nudge parity noted as a follow-up, not blocking.
7. **Nudge comment copy** — **editable in the confirm modal**, not a fixed string. Pre-fill with the current default text, let the user edit before sending (consistent with the app's `askConfirm` modal pattern).
8. **Phase ordering** — **keep A → B → C first**, then D/E/F in any order, then G. The real-time refresh is the headline "wow" of this release and unlocks C/G/the indexing hook; D/E/F remain independent and can be picked up in parallel if desired.
